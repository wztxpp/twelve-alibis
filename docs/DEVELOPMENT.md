# 开发与内容编辑

## 结构与边界

界面使用Vue3响应式状态和组件模板，不通过旧版DOM脚本拼装应用。谜题逻辑独立于界面；朗读控制器独立于人物选择。编辑样式不会改变谜题，编辑证词文本却可能改变逻辑含义，须一起校验。

## 谜题数据

每章包括：

- `id`：存档键。改变谜题答案时应换新id，避免沿用旧存档。
- `prologue` / `briefing`：调查简报和任务。实际展示的 prologue 由 `story.js` 按章节 id 合并；不要在叙事覆盖中删除公开硬条件。
- `story.js` 的 `opening` / `ending`：逐句演出，含时间、地点、mood、beats。speaker 为0起始角色编号、字符串角色或null旁白，stage为动作。
- `records`：可查阅现场记录，`carryClues`：前章带来的已核实条件。
- `statements`：每人的`text`与对应`expr`，`speaker`是0起始人物索引。
- `worlds`：所有公开物证允许的事件配置，不能漏掉合法可能。
- `liarCount`：本轮说假话的人数，不是固定反派身份。
- `answer` / `solutionWorld`：唯一答案与完整事件配置。
- `hints` / `solution`：逐步线索与推理。
- `resolution`：纯文字归档后备；实际演出使用 `ending`，答错时不可泄露。

DSL支持相等/不等、同轮/先后、偏移、且/或/非等逻辑组合。复合证词按整句真假计数。改写文字必须保持与表达式等价；例如“至多一个”不等于“恰好一个”。

## 必须保持的行为

1. 每章12位证人，指定隐瞒人数，且仅一个完整解与一个身份集合。晚宴另有调查员“你”和死者韩铮，共14个席位；12是证词提供者的人数，不是晚宴或整艘船的总人数。
2. 前三份证词不能直接揭露答案；自动测试验证候选与子集泄漏。文字/source 与表达式需人工对照，source是人物自述，不是新增的必真物证。
3. 错误提交只说明不成立，不推进剧情或泄露哪人选错。
4. 正确提交进入结局演出；揭晓先展示解答，再明确进入演出。下一章须前章演出完成（或明确跳至场尾后完成）才解锁。
5. 播放证词不切换人物选择；切章、重玩、重置或页面离开停止朗读。
6. 重置清除本篇状态与便签；刷新可保留正常存档。

V5 每章围绕四个与案件直接相关的事件建模，另有声源／控制方式／发起人与目的字段。世界必须穷举公开条件允许的组合；数字与子集验证结果以 `puzzles.json` 的 `verification` 和 `tests/verify-subsets.py` 的实际输出为准。不得用人工挑选候选世界制造唯一解。

## 演出与保存

`useGame` 管理 opening → investigation → ending → closed。`StoryScene` 自行管理本场句序，不自动播放音频；离开组件时关闭记录弹窗。结局完成后显示复盘和下一章入口。减少动态效果设置下取消过渡动画。

存档命名空间为 `twelve-story-v5` 与 `twelve-story-v5-notes`。恢复时验证章节进度链、状态、编号和已读记录。不会读取V4答案；刷新保留当前场景，但从场景首句开始。新证词使用 `last-voyage-*` 章节ID，因此不会播放 `empty-seat-*` 旧录音。游戏显式关闭系统合成朗读回退；没有匹配录音时禁用播放，不擅自替换音色。原始音频文件和录音清单保持不变。

## 美术

现有12幅600×800 WebP按人物顺序对应；替换时保持文件名或同步修改组件引用，提供有意义的alt文字。不需连到AI服务才能运行。

## 测试和发布

先`npm ci`，再`npm run check`。生成的`dist/`可交给常规静态托管。此仓库没有任何生产站点自动部署配置；不要把旧托管系统的内部配置复制进来。语音单元测试使用模拟speechSynthesis，验证取消、回调和错误处理，不代表在每种设备上听过声音。请在目标Windows/Android/iOS浏览器用真实中文音色做最终听音检查。
